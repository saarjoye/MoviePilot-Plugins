# DirUpload115 · MoviePilot v3 插件（目录监控 → 直传 115）

> 一句话：**监控目录 → 目录稳定就整目录上传 115 → 可选触发 CMS 生成 strm**。
> 全程不碰 TMDB、不识别、不重命名、不刮削 —— 只要有视频文件就传。

## 它解决什么问题

MoviePilot 原生整理链是「识别 → 刮削 → 整理 → 入库」的影视逻辑，B站视频没有 TMDB 条目，卡在第一步就传不上 115。
这个插件绕过整条整理链，直接调用宿主的存储能力把文件送进 115：

```
bili-sync / GUI 下载器 → 本地目录 → 【本插件】 → 115 网盘 → CMS 生成 strm → Emby
```

## 依赖（重要）

| 依赖 | 说明 |
|---|---|
| MoviePilot **v3** | 用 v3 的稳定 SDK：`app.sdk.plugin._PluginBase` |
| **115 存储插件 `p115disk`（v3）** | 提供 `u115` 存储实现（`get_folder` / `upload_file`）。仓库：`DDSRem-Dev/MoviePilot-Plugins` → `plugins.v3/p115disk`。**装了还要配置 115 Cookie 并启用** |
| 无需 p115client | 本插件里**没有任何 115 协议代码**，全走宿主存储抽象，115 侧逻辑由 `p115disk` 负责（含秒传） |

> 为什么这么设计：`p115disk` 的 `upload_file()` 已经实现好了（含秒传），但它只对外暴露了 `/clear_cache` 一个 API 端点。
> 与其重写 115 协议，不如复用宿主 `StorageChain`，插件只剩「什么时候传、传到哪、传没传过」这点逻辑。

## 安装

1. 装好并启用 MP v3 + `p115disk` 插件（115 Cookie 填好、状态显示已连接）。
2. 把本目录整个拷到 MP 的插件目录：

```bash
# 宿主机（compose 里 /config 映射到哪就放哪）
cp -r plugins/DirUpload115  <你的moviepilot配置目录>/plugins/DirUpload115
# 目录结构必须是：
#   /config/plugins/DirUpload115/__init__.py   ← 类名与目录名一致
```

3. 重启 MoviePilot，在「插件」页找到 **目录监控上传115**，启用并配置。

| 配置 | 默认 | 说明 |

| 启用插件 | 关 | |
| 监控目录 | 空 | **每行一个**，容器内路径；支持 `本地路径 => 115子目录` 映射，如 `/data/bili/合集 => 合集`。省略 `=>` 时默认用本地目录名 |

| 覆盖系列名 / 覆盖 UP 名 | 空 | 系列名默认取父目录或监控目录名；UP 名默认取 NFO 的 actor/role |

**扫描粒度**：只看监控目录的**第一级子目录**，每个子目录 = 一个媒体条目（bili-sync 默认就是「一视频一目录」）。
所以监控 `/data/bili/合集`，产物 `/data/bili/合集/某系列 [BV1aa]/*` → 115 上 `/B站/合集/某系列 [BV1aa]/*`。

## API（可被外部编排调用）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/v1/plugin/DirUpload115/scan` | 立即扫描一轮（鉴权：`auth: bear`，带 MP token） |
| GET | `/api/v1/plugin/DirUpload115/pending` | 查看每个子目录状态（下载中/待上传/done）+ 对应 115 路径 |

## 触发链路：三层「扫描」分别是谁

这条链上有三个完全不同的「扫描」，接错地方会白等：

| 层 | 做什么 | 谁触发 | 本插件角色 |
|---|---|---|---|
| ① **目录扫描（上传）** | 发现「稳定且含视频」的目录 → 上传 115 | 插件自身定时（`扫描周期`）+ 可选外部 webhook `/hook` | 亲自做 |
| ② **CMS 同步（生成 strm）** | 从 115 目录生成 `.strm` + 随行 nfo/图片 | CMS 自己的定时任务；插件上传后会主动调一次 `lift_by_token` | 调 API 触发 |
| ③ **Emby 入库** | 扫 strm 目录，把条目录入媒体库 | **CMS 生成 strm 后自己通知 Emby 刷新**（CMS 里配 `EMBY_HOST_PORT` + `EMBY_API_KEY`） | 不参与，只等 strm 出现 |

顺序是 ①→②→③，插件只做两件事：传完叫 CMS 干活、看到 strm 出现才删本地。第 ③ 层由 CMS 负责，插件不重复触发（避免整库重复扫描）。

### ① 接 bili-sync 的 webhook（可选，省最多一个扫描周期）

bili-sync 的 `notifiers` 支持 webhook（源码 `crates/bili_sync/src/notifier/mod.rs`，serde `tag="type"`）：

```json
{
  "notifiers": [
    {
      "type": "webhook",
      "url": "http://moviepilot:3000/api/v1/plugin/DirUpload115/hook",
      "headers": { "X-API-KEY": "<MoviePilot 的 API_TOKEN>" },
      "template": "{\"event\":\"bili-sync-download-done\"}"
    }
  ]
}
```

- 该端点声明为 `auth: apikey`，专门给容器间调用；正文被忽略，只当作「跑一轮」的信号。
- 如果返回 401，说明这个 MP 版本的插件端点只认用户 JWT —— 直接放弃 webhook，把 `扫描周期` 调成 60 秒即可（本地 stat 目录的开销可以忽略），端到端延迟 ≈ 稳定阈值 + 60 秒。

## 课程模式（1.6.0，按学科/年级册/单元-课题命名）

按「教材章节」组织，而不是按 UP/合集：

```
115：/媒体库/B站/数学/初中七(上)/01 有理数 - 有理数与数轴 - 一数-初中版.mp4
strm：<strm根>/数学/初中七(上)/01 有理数 - 有理数与数轴 - 一数-初中版.nfo + -poster.jpg/-thumb.jpg
```

- **学科**取自 `watch_dirs` 的映射（= 订阅路径里的学科目录），不在文件名里重复；
- **年级/册/章**优先取**内置人教版词典**（按标题里的知识点，29 章 + 专题，零配置）；
  其次看**合集名里的 `【七上】`**（一册一合集的 UP 最省事）；再按 `unmapped_policy` 处理；
- 认错的、词典没收录的，在设置页 **「映射修正」** 多行框里补一行 `BV号 | 学段 | 年级 | 册 | 章号 | 章名 | 课题`，
  保存后下一轮生效；详情页有「待补映射」表格直接给出 BV 号。**不需要 CSV**（CSV 仅作批量导入的可选项）；
- 单集文件名默认 `{unit_no} {unit} - {lesson} - {upper}`，模板变量：`{subject} {stage} {grade} {volume} {unit_no} {unit} {lesson} {upper} {series} {title} {bvid}`；
- **不改本地文件名**（本地是 bili-sync 的记录，动了它会重下）；改名只发生在上传那一刻，和剧集模式一致；
- 结构与剧集模式复用同一套「合集容器」识别，`watch_dirs = /downloads/bili => @auto` 一行就够。

## 课程→剧集模式（一合集 = 一季）

打开 `课程→剧集模式` 后，同一个合集里的每个视频变成「一集」，结构变成 Emby 认的剧集：

```
115：<目标根>/<UP名> - <系列名>/Season 1/<UP名> - <系列名> - S01E01 - 标题.mp4
strm：<strm根>/<UP名> - <系列名>/tvshow.nfo + poster.jpg
                     /Season 1/… - S01E01 - 标题.nfo + -poster.jpg
```

- 115 上仍然**只有视频**；`tvshow.nfo` 和剧集海报由插件在 strm 目录生成（115 上没有，CMS 也就不会产出）。
- **集号持久化**：插件数据里记 `bvid → 集号`。首次按各集 NFO 的 `premiered` 排序定号；之后追更只给新视频分配「最大集号+1」，已入库的集不会被重编号。
- 三个模板：`剧集目录名模板`（默认 `{upper} - {series}`）、`单集文件名模板`（默认 `{show} - S{season:02}E{ep:02} - {title}`）、`季号`。
'- 监控目录**只填一行根目录**（如 `/data/bili/合集`）：插件自动判断子目录是「系列容器」还是「一集」，
  用户不需要手抄带 `|`、`/`、空格的目录名；生成 115/strm 名字时非法字符一律由插件清洗。
- 集号持久化在插件数据 `series_episodes`（`系列名 → {bvid: 集号}`）：追更时新集顺延到「最大集号+1」，
  旧集绝不重编号；若本地缺集导致序号冲突，日志会警告（先全量同步再清空该键即可重排）。'
## 幂等与断点

- 每个媒体目录里会写 `.upload115.state`（**不会被上传**），记录 `status` 与已上传文件清单（文件名 → 字节数）。
- 已有文件按「名字 + 大小」比对，**新增/变化才补传**，不会整目录重传。
- 每传完一个文件就落盘一次状态 → 中途崩溃/重启后只补剩余文件。
- `.upload115.lock` 防止同一目录被两轮扫描同时处理；锁超过 1 小时视为失效。
- 目录里出现 .upload115.state 的 status: done 即跳过；status: waiting_strm 表示已上传、正在等 strm（不会重复上传）；想重传就删掉它。

## 上传后删本地（安全设计）

本地删除不可逆，所以「什么时候算真的成功」是一个可配置的开关，四档：

| 判定依据 | 判据 | 额外开销 | 适合 |
|---|---|---|---|
| `strm`（默认） | CMS 已产出同名 `.strm` | 无（读本地目录） | 信任 CMS 的通知链路 |
| **`emby`** | strm 有了 **且** Emby 里能查到这条 strm | 每次多一次 Emby 查询 | 想连「Emby 真入库」一起验证 |
| `storage` | 回查 115 目录，文件名 + 字节大小全对得上 | 每次多一次 115 列举 | 怀疑秒传丢文件 |
| `none` | 上传成功即算成功 | 无 | 不推荐 |

```
上传全部文件 → 状态置 waiting_strm（不访问 115）
  ↓
每轮扫描先看 CMS 的 strm 输出目录：同名 .strm 是否存在且非空
  ↓ 选了 emby 模式：再问 Emby「这条 strm 入库了吗」
  ↓ 未就绪 → 继续等（只记日志，不删）
  ↓ 超时（默认 1800s）→ 告警一次，继续等，绝不删本地
  ↓ 就绪 → 写 done + 台账 → 按 delete_mode 处理本地
```

`emby` 模式的匹配用的是**相对路径后缀**（`<映射子目录>/<媒体目录>/<文件名>.strm`），不是绝对路径 —— 因为 Emby 容器里的挂载点和插件配置的 `strm_root` 经常不一致（`/media/strm/B站` vs `D:\strm`），只比后半段才不会误判。

**为什么默认用 strm 而不是回查 115**：strm 是 CMS 读 115 目录后生成的，它出现本身就证明「115 侧文件已可读、CMS 已同步」，还少一层 115 接口调用，避免触发风控。但它**不包含**「Emby 真的入库」——CMS 的 `EMBY_API_KEY` 配错时会静默失败，strm 照生成。想把这层也堵上就选 `emby` 模式。

- `recycle` 模式把目录整棵移到 `<回收目录>/<YYYYMMDD>/<目录名>/`；`delete` 模式 `rmtree` 并清空上级空目录；`none` 只记录不清理。
- 台账（`get_data("ledger")`，最近 200 条）：本地目录、115 路径、文件数、完成时间、本地处理方式。本地删了之后这是唯一记录。
- 关键：**等待期间插件不会重复上传**（状态是 `waiting_strm`，走到就绪检查分支），也不会因 CMS 延迟而丢掉本地文件。

## 已知限制（说实话的部分）

1. **单目录内串行上传**：一个目录里文件按顺序传（bili-sync 一个目录通常 5~6 个文件，够用）。要并发可以再改。
2. **目录级去重只认「名字 + 大小」**：115 侧被人改过同名文件不会重传；改名视为新文件。
3. **`delete` 模式是真删除且不可恢复**：建议先跑 `recycle` 一两周确认稳定，再切 `delete`。
4. **多文件夹扁平语义**：监控目录下有子目录套子目录时，只按第一级子目录为条目，深层结构原样上传。
5. **没做 CMS 全量同步**：只做「按路径增量」，首次上传建议在 CMS 里手动跑一次全量同步建立基线。
6. **`p115disk` 升级可能改内部契约**：只要它继续实现 v3 storage 契约（`get_folder`/`upload_file`）就不受影响。

## 配置说明（v1.2.1）

### 1. 监控目录 `watch_dirs`
一行一个，格式 `本地目录 => 115 相对子目录`（后半段省略时用本地目录名）：

```
/downloads/bili/数学/一数-初中版-3546913471203629 => 数学
/downloads/bili/语文/梓墨说语文-316069678      => 语文
```

- 本地目录 = bili-sync 的**作者目录**（其下是各个「合集目录」）
- `=> 数学` 就是 115/strm 上的**分类目录**，可以是多层，如 `=> 课程/数学`
- 最终结构：`target_root / 映射目录 / Show(UP名 - 合集名) / Season N / 集文件`
- ⚠️ 不要把映射写成 `数学/作者ID`：v1.2.0 起作者信息已经并入 Show 名，再写会多一层

### 2. 目标与 strm 根
| 配置 | 含义 | 示例 |
|---|---|---|
| `target_root` | 115 上的根目录 | `/媒体库/B站` |
| `strm_root` | 上面那个目录在 MP 容器里对应的本地路径 | `/strm/媒体库/B站` |

两者必须对应同一层，否则 NFO/封面会写到错位置。

### 3. 命名模板
| 配置 | 默认 | 可用变量 |
|---|---|---|
| `show_template` | `{upper} - {series}` | `{upper}` `{series}` `{title}` `{bvid}` `{index}` |
| `episode_template` | `{title}E{ep:02}` | 同上 + `{ep:02}`（两位季集号） |

- `{series}` 取「合集目录名」；当它和 UP 名相同时（投稿/单视频目录）自动替换为 `投稿`
- v1.2.1 起单集额外生成 `<集名>-thumb.jpg`（Emby 单集缩略图规范），Show 级生成 `poster.jpg`/`fanart.jpg`/`tvshow.nfo`

### 4. 就绪判定与清理
| 值 | 含义 |
|---|---|
| `ready_mode = strm` | 本地 strm 目录出现同名 .strm 即算完成（推荐，零 115 请求） |
| `ready_mode = emby` | 查 Emby 已入库才算完成 |
| `ready_mode = storage` | 回查 115 文件存在且大小一致（会消耗 115 请求） |
| `delete_mode = none` | 保留本地（推荐先跑一周） |
| `delete_mode = recycle` | 移入回收目录 `recycle_root/YYYYMMDD/` |
| `delete_mode = delete` | 直接删除该集目录 |

### 5. 已知坑

1. **MP 插件配置是整体覆盖**：只 `PUT {"enabled": true}` 会把其它字段清空，请整表保存
2. **`-thumb.jpg` 与 `-poster.jpg`**：Emby 单集缩略图只认 `-thumb.jpg`
3. **bili-sync 的 `video_name` 必须是 `{{title}}`**（一视频一目录）；如果设成空（扁平布局），本插件的剧集识别会错位
4. 115 有每小时请求上限（QPH），批量上传后不要立刻反复扫描
